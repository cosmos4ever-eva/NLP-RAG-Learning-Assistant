# Graph-RAG 学习助手开发集评测与迭代

## 结论

本轮只使用 24 条 dev，test 24 条保持封存。真实调用 `ecnu-plus` 对 `llm_only`、`tfidf_rag`、`graph_rag` 三组系统生成 72 条回答，模型、temperature=0.3、max_tokens=1200 与题目顺序固定。

| 指标 | 初始版本 | 迭代后 |
|---|---:|---:|
| 课程证据覆盖 | 8/20 (40%) | 18/20 (90%) |
| 原始 Top-3 锚点命中 | 8/20 (40%) | 13/20 (65%) |
| 跨概念证据覆盖 | 1/2 | 2/2 |
| RAG 边界合规 | 4/8 | 8/8 |
| 必需知识关系完整召回 | - | 7/15 (46.7%) |

边界合规为 `4 道边界题 × 2 个 RAG 系统` 的第一轮逐条复核结果；尚待第二名复核者独立标注。它不是 24 道题的总体正确率。

## 真实调用完整性

- 24 个唯一题目、3 个系统、72 个唯一 `(id, system)`，无缺失和重复。
- 平均响应延迟 53.71 秒，最短 25.11 秒，最长 89.82 秒。
- API 返回 usage 合计：67,315 prompt tokens，66,229 completion tokens。
- 原始回答和提示词保存在 `evaluation/private_runs/`，其中含课程片段，不公开提交。

## Bad Case 与迭代

1. 原解析器只扫描 PDF，L2 PPTX 完全缺席。补齐 PPTX 文本解析后，Top-3 锚点命中从 8/20 提升到 13/20。
2. PPT 图表页文本稀疏，且比较题的前三名容易被单一资料占满。加入相邻两页上下文、比较题来源多样性和按页上下文预算后，最终证据覆盖提升到 18/20，跨概念题由 0/2 提升到 2/2。
3. 首轮提示词允许“标注后使用模型知识”，导致模型先说资料不足，随后仍输出 LSTM 公式或推荐 BPE。改为严格课程证据门控后，两个 RAG 系统在四道边界题上由 4/8 提升到 8/8。
4. 仍有两个检索 Bad Case：文本归一化实例与 PMI 低频缺陷距离语义锚点较远。后续应补 OCR、结构化标题或查询改写，不应无限扩大提示词窗口。
5. 必需知识关系只完整召回 7/15，Graph-RAG 的图谱覆盖仍是下一轮重点，不能仅凭本轮结果宣称 Graph-RAG 全面优于普通 RAG。

## 证据边界

- 本轮完成了真实模型调用、开发集检索评测和边界行为迭代。
- 尚未完成 20 道可回答题的双人正确性/依据性全量标注，也未做真实用户学习效果实验。
- test 必须等提示词、检索器和评分表冻结后一次性验收，不能继续用于调参。
